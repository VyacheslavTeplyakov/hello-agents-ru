# Руководство по системе памяти NPC

## Обзор

Теперь NPC кибер-городка обладают **системой памяти**: они помнят историю общения с игроком и используют её в последующих диалогах, становясь умнее и реалистичнее!

---

## Ключевые возможности

### 1. **Рабочая память (Working Memory)** — краткосрочная
- Хранит до 10 последних реплик
- Автоматически устаревает через 2 часа
- Быстрый доступ для контекста текущего диалога

### 2. **Эпизодическая память (Episodic Memory)** — долгосрочная
- Постоянное хранение важных диалогов
- Поддерживает семантический поиск (на основе векторной БД Qdrant)
- Хранится до 100 записей
- Автоматическое забывание записей с важностью ниже 0.3

### 3. **Изоляция памяти**
- Каждый NPC имеет собственную систему памяти
- Память NPC не пересекается между собой
- Диалоги каждого игрока хранятся отдельно

## Примеры использования

### Пример 1. Базовая память о диалоге

```
Первый диалог:
Игрок: «Привет, чем ты занимаешься?»
Иван: «Привет! Я Python-инженер, занимаюсь разработкой мультиагентных систем.»

Второй диалог (через 5 минут):
Игрок: «Помнишь, о чём я тебя только что спрашивал?»
Иван: «Конечно! Ты спрашивал, чем я занимаюсь. Я говорил, что я Python-инженер. Сейчас как раз изучаю фреймворк HelloAgents.»
```

### Пример 2. Долгосрочная память

```
День первый:
Игрок: «Какой твой любимый язык программирования?»
Иван: «Я больше всего люблю Python — он лаконичный, изящный, и у него богатая экосистема.»

День второй:
Игрок: «Мы раньше говорили о языках программирования?»
Иван: «Да, говорили! Помню, я сказал, что больше всего люблю Python. Тебе это интересно?»
```

### Пример 3. Изоляция памяти

```
Разговор с Иваном:
Игрок: «Я сейчас изучаю мультиагентные системы»
Иван: «Отлично! Я как раз этим занимаюсь, спрашивай, если что.»

Разговор с Петром:
Игрок: «О чём я только что говорил с Иваном?»
Пётр: «Извини, я не знаю, о чём вы говорили с Иваном. Я отвечаю за продуктовую сторону.»
```

## Техническая реализация

### Архитектура

```
NPCAgentManager
├── agents: Dict[str, SimpleAgent]          # Агенты NPC
├── memories: Dict[str, MemoryManager]      # Менеджеры памяти NPC
└── chat(npc_name, message, player_id)      # Интерфейс диалога
    ├── 1. Поиск релевантных воспоминаний
    ├── 2. Сборка расширенного промпта
    ├── 3. Вызов агента для генерации ответа
    └── 4. Сохранение диалога в памяти
```

### Структура хранилища памяти

```
backend/memory_data/
├── Иван/
│   ├── sqlite_store.db          # Основная БД SQLite
│   └── qdrant_collection/       # Векторный индекс Qdrant (семантический поиск)
├── Пётр/
│   ├── sqlite_store.db
│   └── qdrant_collection/
└── Сергей/
    ├── sqlite_store.db
    └── qdrant_collection/
```

### Формат данных памяти

```python
{
    "id": "memory_uuid",
    "content": "Игрок сказал: Привет, чем ты занимаешься?",
    "type": "working",  # working/episodic
    "importance": 0.5,  # от 0 до 1
    "timestamp": "2024-01-15T10:30:00",
    "metadata": {
        "speaker": "player",
        "player_id": "player",
        "session_id": "player",
        "context": {
            "interaction_type": "dialogue",
            "npc_name": "Иван"
        }
    }
}
```

## API

### 1. Эндпоинт диалога (с памятью)

```http
POST /chat
Content-Type: application/json

{
    "npc_name": "Иван",
    "message": "Привет, чем ты занимаешься?"
}
```

**Ответ:**
```json
{
    "npc_name": "Иван",
    "npc_title": "Python-инженер",
    "message": "Привет! Я Python-инженер, занимаюсь разработкой мультиагентных систем.",
    "success": true
}
```

### 2. Получить воспоминания NPC

```http
GET /npcs/Иван/memories?limit=10
```

**Ответ:**
```json
{
    "npc_name": "Иван",
    "memories": [
        {
            "id": "uuid-1",
            "content": "Игрок сказал: Привет, чем ты занимаешься?",
            "type": "working",
            "importance": 0.5,
            "timestamp": "2024-01-15T10:30:00",
            "metadata": {...}
        },
        ...
    ],
    "total": 10
}
```

### 3. Очистить память NPC (для тестов)

```http
DELETE /npcs/Иван/memories?memory_type=working
```

**Ответ:**
```json
{
    "message": "Память Ивана очищена",
    "npc_name": "Иван",
    "memory_type": "working"
}
```

## Конфигурация системы памяти

### Параметры (agents.py)

```python
memory_config = MemoryConfig(
    storage_path=f"./memory_data/{npc_name}",  # Путь хранения
    working_memory_capacity=10,                # Объём рабочей памяти
    working_memory_tokens=2000,                # Лимит токенов рабочей памяти
    episodic_memory_capacity=100,              # Объём эпизодической памяти
    enable_forgetting=True,                    # Включить забывание
    forgetting_threshold=0.3                   # Порог забывания
)
```

### Рекомендации

| Параметр | По умолчанию | Рекомендуемый диапазон | Описание |
|----------|--------------|------------------------|----------|
| working_memory_capacity | 10 | 5-20 | Объём рабочей памяти, больше — больше расход памяти |
| working_memory_tokens | 2000 | 1000-4000 | Лимит токенов, влияет на длину контекста |
| episodic_memory_capacity | 100 | 50-500 | Объём долгосрочной памяти, больше — больше места на диске |
| forgetting_threshold | 0.3 | 0.1-0.5 | Порог забывания, ниже — легче забывает |

## Учебная ценность

### Ключевые моменты

1. **Использование MemoryManager**
   - Инициализация менеджера памяти
   - Настройка разных типов памяти
   - Добавление и извлечение воспоминаний

2. **Стратегии извлечения памяти**
   - Рабочая память: быстрый доступ к последним диалогам
   - Эпизодическая память: семантический поиск истории
   - Гибридный поиск: сочетание времени и релевантности

3. **Механизм хранения**
   - SQLite: основное хранилище данных
   - Qdrant: векторный семантический поиск
   - Двойное хранение для согласованности данных

4. **Механизм забывания**
   - Автозабывание по важности
   - TTL-устаревание по времени
   - Приоритетное вытеснение по лимиту

## Частые вопросы

### Q1. Почему NPC не помнит диалог?

**Возможные причины:**
- Система памяти инициализирована неправильно
- Проблемы с правами на путь хранения
- Память удалена механизмом забывания

**Решения:**
- Проверьте, есть ли в логе сообщение «Система памяти инициализирована»
- Убедитесь, что директория memory_data существует
- Увеличьте параметр forgetting_threshold

### Q2. Поиск по памяти неточный?

**Возможные причины:**
- Низкая семантическая схожесть запроса и воспоминаний
- Воспоминания отфильтрованы из-за низкой важности

**Решения:**
- Снизьте параметр min_importance
- Увеличьте limit поиска
- Используйте более конкретные запросы

### Q3. Память занимает слишком много места?

**Решения:**
- Уменьшите episodic_memory_capacity
- Повысьте forgetting_threshold
- Регулярно чистите старые воспоминания
