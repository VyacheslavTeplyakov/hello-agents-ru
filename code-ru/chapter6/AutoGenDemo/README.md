# AutoGen: Команда разработчиков программного обеспечения

В этом каталоге находится полный практический пример из шестой главы фреймворка AutoGen, демонстрирующий, как построить мультиагентную команду для совместной разработки программного обеспечения.

## Файлы

- `autogen_software_team.py` — основной код примера (на основе клиента OpenAI)
- `llm_client.py` — реализация клиента HelloAgentsLLM
- `requirements.txt` — список зависимостей
- `output.py` — пример приложения для отображения курса биткоина, сгенерированного командой
- `README.md` — этот документ

## Особенности примера

- **Совместная работа нескольких агентов**: демонстрирует полный рабочий процесс менеджера продукта, инженера, ревьюера кода и представителя пользователя
- **Реальный сценарий разработки**: полный жизненный цикл разработки от анализа требований до реализации
- **Автоматизированный процесс**: задачи автоматически передаются между агентами без ручного вмешательства
- **Генерация и проверка кода**: автоматическая генерация рабочего кода с последующей проверкой качества

## Подготовка окружения

### 1. Установка зависимостей

```bash
pip install -r requirements.txt
```

### 2. Настройка переменных окружения

Создайте файл `.env` и укажите следующие параметры:

```bash
# Конфигурация LLM
LLM_API_KEY=your-api-key-here
LLM_BASE_URL=https://api.openai.com/v1
LLM_MODEL_ID=gpt-4
```

### 3. Проверка окружения

Убедитесь, что вызов LLM API работает корректно:

```python
import os
from dotenv import load_dotenv
load_dotenv()

print(f"API Key: {os.getenv('LLM_API_KEY')[:10]}...")
print(f"Base URL: {os.getenv('LLM_BASE_URL')}")
print(f"Model: {os.getenv('LLM_MODEL_ID')}")
```

## Запуск примера

### Запустить совместную работу команды разработчиков

```bash
python autogen_software_team.py
```

### Ожидаемый порядок вывода

1. **🔧 Инициализация клиента модели**
2. **👥 Формирование команды агентов**
3. **🚀 Запуск командной работы**
4. **💬 Ход диалога агентов**:
   - ProductManager: анализ требований и техническое планирование
   - Engineer: реализация кода
   - CodeReviewer: проверка кода и рекомендации по улучшению
   - UserProxy: пользовательское тестирование и обратная связь
5. **✅ Работа завершена**

## Описание ролей агентов

### ProductManager (менеджер продукта)
- **Обязанности**: анализ требований, техническое планирование, оценка рисков
- **Результат**: разбивка на функциональные модули, рекомендации по технологиям, критерии приёмки
- **Особенности**: ориентирован на пользовательский опыт и реализуемость продукта

### Engineer (разработчик)
- **Обязанности**: реализация кода, проектирование технических решений
- **Результат**: полный рабочий код
- **Особенности**: Python, Streamlit, интеграция API

### CodeReviewer (ревьюер кода)
- **Обязанности**: проверка качества кода, аудит безопасности
- **Результат**: отчёт по проверке, рекомендации по оптимизации
- **Особенности**: стандарты кода, производительность и безопасность

### UserProxy (представитель пользователя)
- **Обязанности**: представление потребностей пользователя, тестирование, обратная связь
- **Результат**: результаты тестирования, пользовательская обратная связь
- **Особенности**: проверка функций с точки зрения пользователя

## Настройка

### Изменение ролей агентов

Можно настроить поведение агента, изменив `system_message`:

```python
def create_product_manager(model_client):
    system_message = """
    Ты опытный менеджер продукта...
    # Настройте описание роли здесь
    """
    return AssistantAgent(
        name="ProductManager",
        model_client=model_client,
        system_message=system_message,
    )
```

### Настройка рабочего процесса

Можно изменить список участников и условие завершения:

```python
team_chat = RoundRobinGroupChat(
    participants=[
        product_manager,
        engineer,
        code_reviewer,
        user_proxy
    ],
    termination_condition=TextMentionTermination("TERMINATE"),
    max_turns=20,  # Настроить максимальное число ходов
)
```

## Частые вопросы

### В: Агенты не начинают диалог?
О: Проверьте следующее:
- Убедитесь, что ключ API настроен правильно
- Проверьте подключение к сети
- Убедитесь, что имя модели указано верно

### В: Совместная работа прервалась?
О: Возможные причины:
- Ограничения вызовов API
- Сетевой тайм-аут
- Аномальный ответ модели

### В: Сгенерированный код не работает?
О: Рекомендации:
- Убедитесь, что все зависимости установлены
- Проверьте доступность API-интерфейсов
- Изучите логи ошибок для отладки
