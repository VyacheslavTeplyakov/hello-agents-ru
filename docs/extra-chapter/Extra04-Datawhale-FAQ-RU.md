## 1. Мультиагентная архитектура и параллельное выполнение

**В1. Как добиться «многопоточного параллелизма» в мультиагентной системе? Агент-планировщик разбивает задачу на параллельные шаги — как сделать так, чтобы несколько агентов-исполнителей самостоятельно «брали» задачи и автоматически учитывали зависимости? Есть ли готовые фреймворки?**

- Ключевые тезисы:
  - «Агент-планировщик» сначала анализирует зависимости задачи и формирует подзадачи: параллельные и последовательные (с зависимостями).
  - Слой исполнения может быть организован как несколько специализированных агентов, каждый из которых отвечает только за свою подзадачу.
  - Параллельное планирование обычно реализуется через очереди, опрос API и т.п. Большинство сценариев требуют кастомизации под конкретный бизнес — универсального «волшебного» решения не существует.
- Указание на курс: главы о парадигмах мультиагентных систем и системной архитектуре (классические парадигмы + практика с фреймворком).

## 4. Знания и инструменты: RAG / KAG / граф знаний / RL

**В3. Обязательно ли использовать RAG при создании агента?**

- Ключевые тезисы:
  - RAG — не обязательный компонент агента, а один из распространённых видов «инструментов внешних знаний».
  - **Глава 8** реализует RAG с нуля и помогает понять разницу в дизайне системы «с RAG» и «без RAG».
- Указание на курс: Глава 8.
- 🔗 [Глава 8 — Память и поиск](https://github.com/datawhalechina/hello-agents/blob/main/docs/chapter8/)

**В21. Какова связь KAG / графа знаний с агентами?**

- Ключевые тезисы:
  - KAG / граф знаний можно рассматривать как «инструмент» или «базу знаний» агента:
    - Агент отвечает за принятие решений и вызовы;
    - Граф знаний предоставляет структурированные знания и возможности поиска.

**В22. По классификации «обучаемые агенты / агенты на основе LLM» из Главы 1 — к какой категории относятся RL, LLM и RLHF?**

- Ключевые тезисы:
  - RL, LLM и RLHF — скорее **компоненты или реализационные технологии** агента, а не отдельные «типы агентов».
  - Например: LLM может служить «мозгом» агента; RL/RLHF могут использоваться для обучения или дообучки стратегии агента.

**В21. Используемая модель рассуждений поддерживает только потоковый вывод и не может войти в последующий цикл агента.**

- Ключевые тезисы:
  - Модели рассуждений, такие как DeepSeek и Qwen, по умолчанию предоставляют только потоковый API. Необходимо правильно собирать фрагменты — не простой конкатенацией строк (см. Главу 7 с примером правильной сборки).

**В23. Не могу понять, как связать память с базой знаний.**

- Ключевые тезисы:
  - Аналогия: у агента есть кратковременная и долговременная память. Кратковременная — как события за один день, которые мы помним: можно напрямую передать как ввод через контекст. Долговременная — как записная книжка: нельзя сразу передать весь объём в контекст, поэтому создаётся инструмент, который агент может вызвать — модель генерирует запрос и получает ответ из базы знаний через RAG. Это и есть долговременная память.

**В24. Ошибка 403 при запросе к зеркалу Tsinghua.**

- Ключевые тезисы:
  - Сетевая проблема. Замените на зеркало Университета науки и технологий Китая (USTC):
    - https://mirrors.ustc.edu.cn/anaconda/pkgs/main/
    - https://mirrors.ustc.edu.cn/anaconda/pkgs/free/

**В25. Ошибка 401 при вызове API модели.**

- Ключевые тезисы:
  - Недостаточно средств на счёте — необходимо пополнить баланс.

**В27. Ошибка Connection aborted при использовании открытых моделей с Hugging Face.**

- Ключевые тезисы:
  - Сетевая проблема. Рекомендуется настроить `HF_ENDPOINT`.
    - Пример: `code/chapter3/Qwen.py`
    - Зеркало: https://hf-mirror.com

Если возникает ошибка `MaxRetryError("HTTPSConnectionPool(host='huggingface.co', port=443)")`:

Добавьте в код:
```python
import os
os.environ["HF_ENDPOINT"] = "https://hf-mirror.com"
```
Или выполните в командной строке:

(Linux/macOS)
```bash
export HF_ENDPOINT="https://hf-mirror.com"
```
(Windows PowerShell)
```bash
$env:HF_ENDPOINT = "https://hf-mirror.com"
```
