## 1.1 Что такое агент?

При изучении любой сложной концепции лучше всего начинать с чёткого определения. В области искусственного интеллекта **агент** — это любая сущность, которая может воспринимать своё **окружение (Environment)** через **сенсоры (Sensors)** и **автономно** совершать **действия (Actions)** через **исполнительные механизмы (Actuators)** для достижения конкретных целей.

Это определение содержит четыре фундаментальных элемента существования агента:

- **Окружение** — внешний мир, в котором функционирует агент. Для автономного автомобиля это динамично меняющееся дорожное движение; для торгового алгоритма — постоянно изменяющийся финансовый рынок.
- **Сенсоры** — камеры, микрофоны, радары или потоки данных от различных API — всё это расширения перцептивных возможностей агента.
- **Исполнительные механизмы (актуаторы)** — могут быть физическими (роботизированные руки, рулевое управление) или виртуальными (выполнение кода, вызов сервиса).
- **Автономность** — именно она наделяет агента «интеллектом». Агент — не просто программа, пассивно реагирующая на стимулы или строго выполняющая заложенные инструкции. Он принимает самостоятельные решения на основе восприятия и внутреннего состояния для достижения своих целей.

Этот замкнутый цикл «восприятие → действие» составляет основу поведения всех агентов.

### 1.1.1 Агенты с традиционной точки зрения

До нынешней волны **больших языковых моделей (LLM)** пионеры ИИ уже десятилетиями исследовали и строили концепцию «агентов». Эти парадигмы, которые мы сегодня называем «традиционными агентами», прошли чёткий эволюционный путь — от простых к сложным, от пассивного реагирования к активному обучению.

**1. Простые реактивные агенты (Simple Reflex Agents)**

Отправная точка эволюции. Их ядро принятия решений состоит из правил «условие → действие», явно заданных инженерами. Классический пример — автоматический термостат: если температура выше заданного значения, активируется система охлаждения. Такие агенты полностью опираются на текущий ввод, не имеют памяти и предсказательных способностей. Они эффективны, но не способны справляться со сложными задачами, требующими понимания контекста.

**2. Агенты на основе модели (Model-Based Reflex Agents)**

Для решения ограничений реактивных агентов была введена концепция «состояния» и разработаны агенты с внутренней **моделью мира**, отслеживающей аспекты окружения, которые нельзя напрямую воспринять. Пример: автономный автомобиль, въезжая в туннель, где камера временно теряет из виду машину впереди, сохраняет в своей внутренней модели суждение о существовании, скорости и примерном положении этой машины. Это даёт агенту примитивную форму «памяти».

**3. Целеориентированные агенты (Goal-Based Agents)**

Простого понимания мира недостаточно — агенту нужны ясные цели. Такие агенты не просто реагируют на окружение, а активно выбирают действия, ведущие к конкретному будущему состоянию. Вопрос, на который они отвечают: «Что мне делать, чтобы достичь цели?» Классический пример — GPS-навигация: цель — добраться до офиса, агент планирует оптимальный маршрут с помощью алгоритмов поиска (например, A*).

**4. Агенты на основе полезности (Utility-Based Agents)**

В реальном мире цели часто не единственны. Мы хотим не только доехать до офиса, но и быстрее, экономичнее, без пробок. Такие агенты присваивают каждому возможному состоянию мира значение «полезности» и стремятся максимизировать ожидаемую полезность, балансируя между конкурирующими целями.

**5. Обучающиеся агенты (Learning Agents)**

А что если агент мог бы учиться автономно через взаимодействие со средой? Это ключевая идея обучающихся агентов. **Обучение с подкреплением (Reinforcement Learning, RL)** — наиболее показательный путь. Обучающийся агент содержит исполнительный элемент (агент одного из вышеописанных типов) и элемент обучения, который непрерывно корректирует стратегию принятия решений, наблюдая за результатами действий в среде. AlphaGo Zero — вершинное достижение этой философии: через RL в игре го система обнаружила многие эффективные стратегии, превосходящие существующие человеческие знания.

### 1.1.2 Новая парадигма: агенты на основе LLM

Появление больших языковых моделей на основе GPT (Generative Pre-trained Transformer) кардинально меняет методы построения и границы возможностей агентов. Ключевые отличия LLM-агентов от традиционных:

| Измерение | Традиционный агент | LLM-агент |
|-----------|-------------------|-----------|
| Источник знаний | Явно запрограммированный инженерами | Неявно извлечён из массивов данных |
| Обработка языка | Ограниченная, структурированная | Гибкая, высокоуровневая |
| Адаптация | Ограниченная заданными правилами | Общая и гибкая |
| Планирование | Детерминированное | Управляемое моделью |

LLM-агенты могут напрямую обрабатывать высокоуровневые, неоднозначные, контекстно-насыщенные инструкции. Рассмотрим на примере умного туристического помощника:

Получив расплывчатую инструкцию «спланируй поездку в Сямынь», агент:

- **Планирует и рассуждает**: декомпозирует высокоуровневую цель на подзадачи: `[Уточнить предпочтения] → [Запросить информацию] → [Составить маршрут] → [Забронировать билеты и отель]`
- **Использует инструменты**: вызывает внешние API (погода, карты, бронирование) для заполнения информационных пробелов
- **Динамически адаптируется**: учитывает обратную связь («этот отель превышает бюджет») и корректирует последующие действия

### 1.1.3 Типы агентов

Агентов можно классифицировать по трём взаимодополняющим измерениям.

**(1) По внутренней архитектуре принятия решений**

Классическая классификационная лестница, описанная выше: реактивные → на основе модели → целеориентированные → на основе полезности → обучающиеся.

**(2) По времени реакции**

- **Реактивные агенты** — почти мгновенный ответ на стимулы. Преимущество: скорость и малые вычислительные затраты. Недостаток: «близорукость», неспособность к долгосрочному планированию. Примеры: система подушек безопасности, алгоритмы высокочастотной торговли.

- **Рефлексирующие агенты (deliberative)** — сначала думают, потом действуют. Аналогия: шахматист, который просчитывает не только следующий ход, но и десятки ходов вперёд. Преимущество: стратегичность и дальновидность. Недостаток: высокие временны́е и вычислительные затраты.

- **Гибридные агенты** — объединяют оба подхода. Нижний уровень: быстрый реактивный модуль; верхний уровень: модуль рефлексивного планирования. Современные LLM-агенты работают именно в таком режиме через цикл «думай → действуй → наблюдай»:
  - **Рассуждение** (фаза «думать») — рефлексивный процесс
  - **Действие и наблюдение** — реактивный процесс

**(3) По типу представления знаний**

- **Символический ИИ (Symbolic AI / Symbolism)** — интеллект из логических операций над символами (словами, концепциями). Знания хранятся в явных правилах и базах знаний. Преимущество: прозрачность и интерпретируемость. Недостаток: хрупкость («узкое место приобретения знаний» — любая непредвиденная ситуация может вызвать сбой).

- **Субсимволический ИИ (Sub-symbolic AI / Connectionism)** — знания неявно распределены в нейронной сети в виде статистических паттернов, извлечённых из массивов данных. Преимущество: распознавание паттернов, устойчивость к зашумлённым данным. Недостаток: «чёрный ящик», склонность к галлюцинациям.

- **Нейросимволический ИИ (Neuro-Symbolic AI)** — «великое примирение» двух лагерей. Цель: создать гибридные агенты, которые могут и учиться из данных как нейронные сети, и рассуждать логически как символические системы.

  Отличная аналогия — теория двух систем мышления Даниэля Канемана («Думай медленно... решай быстро»):
  - **Система 1** — быстрое, интуитивное, параллельное мышление ≈ субсимволический ИИ
  - **Система 2** — медленное, методичное, логическое мышление ≈ символический ИИ

  LLM-агенты — отличный практический пример нейросимволизма: нейронная сеть (LLM) + явные структурированные шаги (мысли, планы, вызовы API).

## 1.2 Состав и принципы работы агентов

### 1.2.1 Определение задачной среды: модель PEAS

Чтобы понять, как работает агент, нужно прежде понять **задачную среду**, в которой он функционирует. В ИИ-сообществе для точного описания задачной среды используется модель **PEAS**:

- **P**erformance measure — Метрика производительности
- **E**nvironment — Окружение
- **A**ctuators — Исполнительные механизмы
- **S**ensors — Сенсоры

Пример PEAS-описания умного туристического помощника:

| PEAS-компонент | Описание |
|---|---|
| **Метрика** | Удовлетворённость пользователя, точность рекомендаций, время выполнения задачи |
| **Окружение** | Интернет, API погоды, системы бронирования, предпочтения пользователя |
| **Исполнительные механизмы** | Вызовы API, текстовые ответы, обновления бронирований |
| **Сенсоры** | Текстовый ввод пользователя, данные API, результаты поиска |

**Характеристики окружения в реальных LLM-агентах:**

- **Частично наблюдаемое**: агент не может получить всю информацию сразу (например, не видит цены на все рейсы одновременно)
- **Стохастическое (недетерминированное)**: два последовательных запроса цен могут вернуть разные результаты
- **Мультиагентное**: другие пользователи, скрипты, динамические системы ценообразования авиакомпаний — тоже «агенты» в этой среде
- **Последовательное и динамическое**: текущие действия влияют на будущее; среда меняется, пока агент принимает решение

### 1.2.2 Механизм работы агента: цикл агента

Агент не выполняет задачи за один шаг — он взаимодействует со средой через непрерывный цикл. Это называется **Цикл агента (Agent Loop)**:

1. **Восприятие (Perception)**: агент получает входную информацию из среды через сенсоры — инструкцию пользователя или обратную связь от предыдущего действия
2. **Мышление (Thought)**: стадия принятия решений, управляемая LLM:
   - **Планирование**: на основе наблюдений и памяти агент формирует или корректирует план действий
   - **Выбор инструмента**: из доступных инструментов выбирается наиболее подходящий
3. **Действие (Action)**: агент выполняет конкретные действия через исполнительные механизмы (вызов инструмента, запрос к API)

Действие изменяет состояние среды → среда производит новое наблюдение → агент снова воспринимает его. Так формируется непрерывный замкнутый цикл «воспринимай → думай → действуй → наблюдай».

### 1.2.3 Восприятие и действие агента: протокол взаимодействия

В современных агентных фреймворках вывод агента структурирован: не просто текст на естественном языке, а специальный формат с двумя ключевыми частями:

- **Thought (Мысль)** — «снимок» внутреннего процесса принятия решений. Агент формулирует на естественном языке, как анализирует ситуацию, рефлексирует над результатами предыдущего шага и планирует следующее действие.
- **Action (Действие)** — конкретная операция, как правило, вызов функции.

Пример структурированного вывода агента:
```
Thought: Пользователь хочет узнать погоду в Пекине. Мне нужно вызвать инструмент запроса погоды.
Action: get_weather("Beijing")
```

После выполнения действия среда возвращает результат. Система восприятия преобразует его из машиночитаемого формата (JSON) в естественный язык:
```
Observation: Текущая погода в Пекине: солнечно, температура 25 °C, лёгкий ветер.
```

Это `Observation` поступает агенту как входная информация для следующего раунда цикла.

```python
import requests

def get_weather(city: str) -> str:
    url = f"https://wttr.in/{city}?format=j1"
    try:
        response = requests.get(url)
        response.raise_for_status()
        data = response.json()
        current_condition = data['current_condition'][0]
        weather_desc = current_condition['weatherDesc'][0]['value']
        temp_c = current_condition['temp_C']
        return f"Текущая погода в {city}: {weather_desc}, температура {temp_c} °C"
    except requests.exceptions.RequestException as e:
        return f"Ошибка: проблема с сетью при запросе погоды — {e}"
    except (KeyError, IndexError) as e:
        return f"Ошибка: не удалось разобрать данные о погоде, возможно неверное название города — {e}"
```

**(3) Инструмент 2: поиск и рекомендация достопримечательностей**

```python
import os
from tavily import TavilyClient

def get_attraction(city: str, weather: str) -> str:
    api_key = os.environ.get("TAVILY_API_KEY")
    if not api_key:
        return "Ошибка: переменная окружения TAVILY_API_KEY не настроена."
    tavily = TavilyClient(api_key=api_key)
    query = f"Самые стоящие достопримечательности '{city}' при погоде '{weather}'"
    try:
        response = tavily.search(query=query, search_depth="basic", include_answer=True)
        if response.get("answer"):
            return response["answer"]
        formatted_results = [f"- {r['title']}: {r['content']}" for r in response.get("results", [])]
        if not formatted_results:
            return "К сожалению, подходящих достопримечательностей не найдено."
        return "На основе поиска найдено:\n" + "\n".join(formatted_results)
    except Exception as e:
        return f"Ошибка при поиске через Tavily — {e}"

# Все инструменты в одном словаре
available_tools = {
    "get_weather": get_weather,
    "get_attraction": get_attraction,
}
```

### 1.3.2 Подключение к LLM

```python
from openai import OpenAI

class OpenAICompatibleClient:
    def __init__(self, model: str, api_key: str, base_url: str):
        self.model = model
        self.client = OpenAI(api_key=api_key, base_url=base_url)

    def generate(self, prompt: str, system_prompt: str) -> str:
        print("Вызов языковой модели...")
        try:
            messages = [
                {'role': 'system', 'content': system_prompt},
                {'role': 'user', 'content': prompt}
            ]
            response = self.client.chat.completions.create(
                model=self.model,
                messages=messages,
                stream=False
            )
            answer = response.choices[0].message.content
            print("Модель успешно ответила.")
            return answer
        except Exception as e:
            print(f"Ошибка при вызове LLM API: {e}")
            return "Ошибка: проблема при обращении к языковой модели."
```

```python
    print(f"--- Итерация {i+1} ---\n")
    full_prompt = "\n".join(prompt_history)
    llm_output = llm.generate(full_prompt, system_prompt=AGENT_SYSTEM_PROMPT)
    # Обрезаем лишние пары Thought-Action, которые может сгенерировать модель
    match = re.search(r'(Thought:.*?Action:.*?)(?=\n\s*(?:Thought:|Action:|Observation:)|\Z)',
                      llm_output, re.DOTALL)
    if match:
        truncated = match.group(1).strip()
        if truncated != llm_output.strip():
            llm_output = truncated
    print(f"Вывод модели:\n{llm_output}\n")
    prompt_history.append(llm_output)

    action_match = re.search(r"Action: (.*)", llm_output, re.DOTALL)
    if not action_match:
        observation = "Ошибка: действие не найдено."
        prompt_history.append(f"Observation: {observation}")
        continue

    action_str = action_match.group(1).strip()
    if action_str.startswith("Finish"):
        final_answer = re.match(r"Finish\[(.*)\]", action_str).group(1)
        print(f"Задача выполнена. Финальный ответ: {final_answer}")
        break

    tool_name = re.search(r"(\w+)\(", action_str).group(1)
    args_str = re.search(r"\((.*)\)", action_str).group(1)
    kwargs = dict(re.findall(r'(\w+)="([^"]*)"', args_str))

    observation = available_tools[tool_name](**kwargs) if tool_name in available_tools \
        else f"Ошибка: неизвестный инструмент '{tool_name}'"

    observation_str = f"Observation: {observation}"
    print(f"{observation_str}\n" + "="*40)
    prompt_history.append(observation_str)
```

### 1.3.4 Анализ выполнения

Пример успешного прогона (три итерации):

```
Итерация 1:
  Thought: Нужно узнать погоду в Пекине, затем — рекомендовать достопримечательность.
  Action: get_weather(city="Beijing")
  Observation: Текущая погода в Пекине: солнечно, температура 26 °C

Итерация 2:
  Thought: Погода солнечная, умеренная температура. Рекомендую достопримечательности для такой погоды.
  Action: get_attraction(city="Beijing", weather="Sunny")
  Observation: В солнечную погоду в Пекине стоит посетить Летний дворец и Великую стену.

Итерация 3:
  Thought: Получены рекомендации, готов дать финальный ответ.
  Action: Finish[Сегодня в Пекине солнечно, 26 °C. Рекомендую Летний дворец с видом на озеро Куньмин или Великую стену с её грандиозными пейзажами.]
```

Кейс демонстрирует четыре базовые способности агента на парадигме `Thought-Action-Observation`:
1. **Декомпозиция задачи** — разбивка задачи на подзадачи
2. **Вызов инструментов** — выбор и применение подходящего инструмента
3. **Понимание контекста** — использование результатов предыдущего шага в следующем
4. **Синтез результатов** — сборка финального ответа

## 1.4 Режимы взаимодействия агентных приложений

### 1.4.1 Агенты как инструменты разработчика

В этом режиме агенты глубоко интегрированы в рабочие процессы разработчиков, автоматизируя рутинные задачи. Примеры популярных инструментов:

- **GitHub Copilot** — автодополнение кода прямо в редакторе (VS Code и др.), поддержка чата через Copilot Chat
- **Claude Code** — программирование через терминал с помощью естественного языка; понимает структуру всей кодовой базы, выполняет редактирование, тестирование, отладку; поддерживает headless-режим для CI и автоматизации
- **Cursor** — AI-native редактор кода, где AI-взаимодействие встроено в дизайн с самого начала; глубоко понимает контекст всей кодовой базы

### 1.4.2 Агенты как автономные коллаборанты

В этом режиме агентам делегируется высокоуровневая цель, которую они самостоятельно планируют, выполняют и рефлексируют. Основные архитектурные парадигмы:

1. **Автономный цикл одного агента** — агент непрерывно рассуждает в петле «думай → планируй → выполняй → рефлексируй» (например, AgentGPT)

2. **Мультиагентное взаимодействие** — несколько агентов с разными ролями совместно решают задачи:
   - **Ролевой диалог** (CAMEL): два агента — «программист» и «менеджер продукта»
   - **Организованный рабочий процесс** (MetaGPT, CrewAI): «виртуальная команда» с чётким распределением обязанностей и SOP
   - **Гибкие сети взаимодействия** (AutoGen, AgentScope): разработчики сами настраивают сложные сети взаимодействия между агентами

3. **Архитектуры управления потоком** (LangGraph): граф состояний для агентского процесса — циклы, ветвления, откаты, вмешательство человека

### 1.4.3 Workflow против Agent: в чём разница?

Простая формула: **Workflow заставляет ИИ выполнять инструкции шаг за шагом; Agent даёт ИИ свободу автономно достигать целей.**

| Характеристика | Workflow | Agent |
|---|---|---|
| Логика | Предопределённый структурированный порядок | Автономное рассуждение и планирование |
| Гибкость | Ограниченная — точная статическая блок-схема | Высокая — динамическая адаптация |
| Применение | Повторяющиеся, чётко определённые процессы | Сложные, непредсказуемые задачи |

Пример Workflow — процесс утверждения расходов: сумма < 500 → руководитель отдела → → CFO → финансовый отдел. Каждый шаг и условие жёстко заданы.

Агент же, получив инструкцию «проверь погоду в Пекине и порекомендуй достопримечательность», самостоятельно рассуждает: «Солнечная погода → подходят открытые площадки» — без жёстко закодированных правил. Если погода дождливая, агент автономно порекомендует крытые музеи. **Способность к динамическому рассуждению на основе реальной информации — это и есть ключевая ценность агентов.**

- **Что такое агенты?** Современные агенты — не просто скрипты, выполняющие заданные программы, а принимающие решения системы, способные к автономному рассуждению и использованию инструментов.
- **Как работают агенты?** Через непрерывный замкнутый цикл «воспринимай → думай → действуй → наблюдай».
